## 🔄 Iterative Workflow Established

### Standard Process

1. **Test Current State**
   ```bash
   node scripts/lighthouse-test.mjs
   ```

2. **Review Report**
   ```bash
   cat LIGHTHOUSE-REPORT.md
   ```

3. **Identify Issues**
   - Scores below 90
   - LCP > 2.5s on mobile
   - TBT > 200ms
   - Top opportunities with significant savings

4. **Implement Fixes**
   - Add `loading="lazy"` to below-fold images
   - Add `fetchpriority="high"` to LCP element
   - Defer non-critical JavaScript
   - Preload critical resources
   - Reduce unused CSS

5. **Build & Deploy**
   ```bash
   pnpm build
   git add -A
   git commit -m "Performance: [description]"
   git push
   ```

6. **Wait & Retest** (GitHub Pages takes ~3 minutes)
   ```bash
   sleep 180
   node scripts/lighthouse-test.mjs
   ```

7. **Compare & Iterate**
   - Check score improvements
   - Repeat if needed

## 🔍 Technical Insights

### What Already Works Well

1. **BlurImage Component** (`src/components/BlurImage.astro`)
   - ThumbHash placeholders for instant blur preview
   - `fetchpriority="high"` support for LCP images
   - `loading="eager"` for above-fold, `"lazy"` for below-fold
   - WebP with responsive srcsets (400w, 800w)
   - Progressive enhancement with canvas blur

2. **Idle Processing**
   - ThumbHash processing uses `requestIdleCallback`
   - Batched processing (4 images at a time)
   - Avoids blocking main thread

3. **Priority Hints**
   - First 6 cards on `/coins` and `/artifacts` have `priority={true}`
   - Maps to `fetchpriority="high"` in BlurImage

4. **Dynamic Imports**
   - Timeline component loaded dynamically to reduce initial bundle

### Areas for Future Optimization

1. **CSS Bundle Size**
   - Currently showing 11-14 KiB unused CSS
   - Tailwind PurgeCSS is configured but could be optimized further
   - Consider per-route CSS splitting

2. **Collection Page LCP**
   - Mobile LCP at 3.2-3.3s on Coins/Artifacts
   - Could preload first image or use even more aggressive priority
   - Network latency is main factor (images are already optimized)

3. **Articles Page Mobile**
   - Currently 84/100 after lazy loading fix
   - May benefit from preloading first article thumbnail
   - TBT at 130ms is acceptable but could be reduced

4. **Service Worker**
   - No offline support currently
   - Could cache images and pages for repeat visits

## 📚 Key Learnings

### 1. Test Production URLs Directly
- GitHub Pages redirects add 400-2600ms of artificial latency
- Always test the actual production domain (`theantiquearchive.com`)
- Avoid testing intermediate URLs that redirect

### 2. Lazy Loading is Critical
- Below-fold images should always have `loading="lazy"`
- Eager loading everything hurts mobile LCP significantly
- Only first viewport images should be eager

### 3. Lighthouse Local > PageSpeed API
- PageSpeed API has aggressive rate limits
- Local Lighthouse is more reliable and faster
- Can run repeatedly without hitting limits

### 4. Small Changes, Big Impact
- Adding `loading="lazy"` to 2-3 images can improve scores by 10+ points
- `fetchpriority="high"` on LCP element can shave off 500ms+
- Measure before and after to validate impact
